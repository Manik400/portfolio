01 · PARKNEST · NO DOUBLE-BOOK, NO DOUBLE-CHARGE

Two renters, one slot, same millisecond.

Alice and Bob both read "slot 3 is free" and both submit. Without a version check the second write silently overwrites the first and both get a confirmation. With optimistic concurrency the stale write is rejected. Then the payment: a client retry with the same idempotency key must not charge twice.

02 · BULK ENROLLMENT · 5,000 RECORDS · SERVER-SIDE VALIDATION · LIVE PROGRESS

Upload a messy sheet. Get a clean answer, row by row.

Operators upload Excel sheets of people to enroll. Some rows are broken — bad IDs, duplicate emails, missing photos. The server validates every field, streams progress over a SignalR hub instead of making the browser poll, and returns exactly which rows failed and why, so the operator fixes 40 rows instead of re-uploading 5,000.

03 · VECTOR SEARCH · WATCHLIST MATCH & DEDUP · −75% INDEX MEMORY

Is this face already enrolled?

Every enrollment produces an embedding. Before inserting, the service searches the index for near-duplicates above a similarity threshold — otherwise the same person ends up enrolled four times and the watchlist fires four alerts. Click anywhere to "enroll" a new embedding; drag the threshold to see dedup get stricter. The index toggle shows the memory trade-off I tuned.
