01 · PARKNEST · NO DOUBLE-BOOK, NO DOUBLE-CHARGE

Two renters, one slot, same millisecond.

Alice and Bob both read "slot 3 is free" and both submit. Without a version check the second write silently overwrites the first and both get a confirmation. With optimistic concurrency the stale write is rejected. Then the payment: a client retry with the same idempotency key must not charge twice.

OPTIMISTIC CONCURRENCYUPDATE … WHERE id=3 AND version=@seen — 0 rows affected ⇒ conflict
